Setup

Introduction to RNA-seq Data Analysis Workshop
Gladstone Institutes Bioinformatics Core

Workshop date: September 28-29, 2026

Complete this setup before the workshop begins.

Workshop overview

This 2-session workshop teaches RNA-seq data analysis from raw sequencing reads to gene count matrices. You will run each step of the pipeline individually using industry-standard bioinformatics tools inside a Docker container.

Dataset:

  • Human chromosome 16 (subset for fast processing)
  • 2 paired-end RNA-seq samples (Illumina paired-end reads, R1 and R2 per sample):
    • N61311_dex: dexamethasone-treated airway smooth muscle cells
    • N61311_untrt: untreated control

Schedule:

Session Topic Tools Guide
1 Quality Control and Trimming FastQC, cutadapt Part 1: Quality Control
2 Alignment and Quantification STAR or HISAT2, featureCounts Part 2: Alignment and Quantification

Folder contents:

├── fastq/                          Raw sequencing data

Prerequisites

1. Install Docker Desktop

Docker lets you run all bioinformatics tools without installing them individually. Everything runs inside a pre-built container.

Download: https://www.docker.com/products/docker-desktop/

Mac:

  1. Download Docker Desktop for Mac
    • Choose Apple Silicon for M1/M2/M3/M4 Macs
    • Choose Intel for Intel Macs
  2. Open the .dmg file and drag Docker to Applications
  3. Launch Docker Desktop and wait for the whale icon in the menu bar to stop animating
NoteCommon Mac pitfalls
  • Not sure which Mac you have? Click the Apple menu > About This Mac. Look for “Apple M1/M2/M3/M4” (Apple Silicon) or “Intel”.
  • Apple Silicon Macs require --platform linux/amd64 in Docker commands. This is already included in the workshop guides.
  • First launch can take 1-2 minutes. Wait for the whale icon to be steady.

Windows:

  1. Download Docker Desktop for Windows
    • Most users: choose AMD64 (for Intel or AMD processors)
    • Surface Pro X or Snapdragon laptops: choose ARM64
    • Not sure? Choose AMD64. It works on the vast majority of Windows computers
  2. Run the installer and follow the prompts
  3. Restart your computer when prompted
  4. Launch Docker Desktop
NoteCommon Windows pitfalls

  • If you see “WSL 2 is not installed”, open PowerShell as Administrator and run:

    wsl --install

    then restart.

  • If you see “Hardware assisted virtualization is not enabled”, you need to enable it in your BIOS settings. Search “[your computer brand] enable virtualization” for instructions.

  • Windows paths use backslashes: C:\Users\YourName\Downloads\...

Linux:

  1. Download and install Docker Desktop for Linux from the link above
  2. Launch Docker Desktop

2. Verify Docker installation

Open your terminal:

  • Mac: Press Cmd + Space, type Terminal, press Enter
  • Windows: Press the Windows key, type cmd, press Enter
  • Linux: Press Ctrl + Alt + T

Run:

docker --version

You should see the Docker version printed. Then verify it can run containers:

docker run hello-world

If you see “Hello from Docker!”, you are ready.

3. Download the Docker image

In the same terminal, run:

docker pull nfcore/rnaseq

This downloads about 3 GB and may take several minutes. You only need to do this once.

Verify the image was downloaded:

docker images

You should see nfcore/rnaseq in the list. This confirms the image was downloaded successfully.

4. Place the workshop folder

Put the workshop folder in an easy-to-find location. Note the full path. You will need it when launching Docker.

OS Suggested location
Mac ~/Downloads/Intro_to_RNA-seq_data_analysis
Windows C:\Users\YourName\Downloads\Intro_to_RNA-seq_data_analysis
Linux ~/Downloads/Intro_to_RNA-seq_data_analysis

Understanding Docker

What is Docker?

Think of Docker as a portable lab bench. When you run a Docker container, you get a mini Linux computer inside your computer with all the tools pre-installed. When you are done, you close the container, but your data stays on your computer.

Volume mounting

The -v flag creates a live connection between a folder on your computer and a folder inside the container:

Your Computer                          Docker Container
┌─────────────────────────┐            ┌─────────────────────────┐
│ Workshop folder/         │  ◄══════►  │ /data/                  │
│   ├── fastq/             │            │   ├── fastq/            │
│   ├── reference_genome/  │            │   ├── reference_genome/ │
│   ├── trimmed_reads/     │            │   ├── trimmed_reads/    │
│   └── aligned_reads/     │            │   └── aligned_reads/    │
└─────────────────────────┘            └─────────────────────────┘
        PERSISTS                                TEMPORARY
   (always on your disk)               (gone when container exits)

What persists vs. what doesn’t

Item Persists after exit? Why
Files in /data Yes Stored on your computer via mount
FASTQ, SAM, index files in /data Yes Written to mounted folder
Installed packages inside container No Part of the container
Command history No Part of the container

The rule: Everything inside /data persists. Everything outside /data disappears.

Container lifecycle

docker run --name rnaseq_day1 ...     # create and start the container
exit                                   # stop the container
docker rm rnaseq_day1                  # delete the stopped container
docker run --name rnaseq_day2 ...      # new container, same files!

Troubleshooting

“Container name already in use”

docker: Error response from daemon: Conflict. The container name "/rnaseq_day1" is already in use

Fix: remove the old container and try again:

docker rm rnaseq_day1

Files missing inside container

ls /data shows nothing or is missing files. Check:

  1. Is Docker Desktop running?
  2. Is the path in your -v flag correct?
  3. Do the files exist in your workshop folder on your computer?

“Cannot connect to the Docker daemon”

Fix: open Docker Desktop and wait for it to fully start (whale icon stops animating).

Docker is slow on Apple Silicon Macs

On M1/M2/M3/M4 Macs, Docker runs through an emulation layer. This is normal. Steps like STAR indexing will take longer than on Intel systems.

Restarting a stopped container

If you exited a container but did not remove it, you can restart it:

docker ps -a   # list all containers
docker start -i rnaseq_day1   # restart the container
