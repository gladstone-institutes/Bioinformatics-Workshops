Part 1: Quality Control and Trimming

Introduction to RNA-seq Data Analysis Workshop
Gladstone Institutes Bioinformatics Core

Workshop date: September 28-29, 2026

Goals

  1. Assess the quality of raw sequencing reads using FastQC
  2. Trim adapter sequences and low-quality bases using cutadapt
  3. Verify that trimming improved read quality

Before you start

  • Docker Desktop is running (whale icon in menu bar / system tray)
  • You downloaded the Docker image (docker pull nfcore/rnaseq)
  • You know the path to your workshop folder

If you haven’t done this yet, see Setup.

Step 1: Launch the Docker container

Open your terminal and run the command for your operating system. This starts a Linux container with all bioinformatics tools pre-installed and connects your workshop folder to /data inside the container.

Mac (Apple Silicon, M1/M2/M3/M4):

docker run --platform linux/amd64 --name rnaseq_day1 \
  -v ~/Downloads/Fall_2026_IntroRNAseq_handson_Session_I-II:/data \
  -it nfcore/rnaseq bash

Mac (Intel) / Linux:

docker run --name rnaseq_day1 \
  -v ~/Downloads/Fall_2026_IntroRNAseq_handson_Session_I-II:/data \
  -it nfcore/rnaseq bash

Windows (Command Prompt):

docker run --name rnaseq_day1 -v C:\Users\YourName\Downloads\Fall_2026_IntroRNAseq_handson_Session_I-II:/data -it nfcore/rnaseq bash

Replace YourName with your actual Windows username.

What each part means:

Part Meaning
docker run Create and start a new container
--platform linux/amd64 (Apple Silicon only) Run the Linux/Intel version
--name rnaseq_day1 Name this container “rnaseq_day1”
-v .../:/data Mount your workshop folder to /data inside the container
-it Interactive mode with a terminal
nfcore/rnaseq Docker image with bioinformatics tools
bash Start a bash shell

Your terminal prompt will change. You are now inside the Docker container.

Tip

If you see “container name already in use”, run docker rm rnaseq_day1 and try again.

Step 2: Navigate to your data and verify files

cd /data
ls -lh fastq/

You should see 4 FASTQ files:

N61311_dex_R1.fastq.gz
N61311_dex_R2.fastq.gz
N61311_untrt_R1.fastq.gz
N61311_untrt_R2.fastq.gz

Also check the reference genome:

ls -lh reference_genome/

You should see chr16.fa and chr16.gtf.

Step 3: Run FastQC on raw reads

FastQC generates quality reports for each FASTQ file. These reports tell you about read quality, adapter contamination, and other potential issues.

mkdir -p fastqc_raw
fastqc -o fastqc_raw \
  fastq/N61311_dex_R1.fastq.gz \
  fastq/N61311_dex_R2.fastq.gz \
  fastq/N61311_untrt_R1.fastq.gz \
  fastq/N61311_untrt_R2.fastq.gz
Parameter Meaning
-o fastqc_raw Save output to the fastqc_raw/ directory
The FASTQ files Input files to analyze

Output files (in fastqc_raw/):

  • *.html: Quality reports you can open in a web browser
  • *.zip: Raw FastQC data files

To view the reports: on your computer (not inside Docker), navigate to the workshop folder, open fastqc_raw/, and double-click any .html file.

What to look for:

  • Per base sequence quality: Green = good (scores above 28). Some decline at the ends is normal.
  • Adapter content: A rising curve means adapters need to be trimmed.
  • Sequence length distribution: Should show a single peak at your read length.

Step 4: Trim adapters and low-quality bases with cutadapt

cutadapt removes adapter sequences added during library preparation and trims bases with low quality scores from the ends of reads.

mkdir -p trimmed_reads

Sample 1: Dexamethasone-treated

cutadapt \
  -a AGATCGGAAGAGCACACGTCTGAACTCCAGTCA \
  -A AGATCGGAAGAGCGTCGTGTAGGGAAAGAGTGT \
  -q 20 \
  -m 36 \
  -o trimmed_reads/N61311_dex_R1_trimmed.fastq.gz \
  -p trimmed_reads/N61311_dex_R2_trimmed.fastq.gz \
  fastq/N61311_dex_R1.fastq.gz \
  fastq/N61311_dex_R2.fastq.gz \
  > trimmed_reads/N61311_dex_cutadapt.log

Sample 2: Untreated control

cutadapt \
  -a AGATCGGAAGAGCACACGTCTGAACTCCAGTCA \
  -A AGATCGGAAGAGCGTCGTGTAGGGAAAGAGTGT \
  -q 20 \
  -m 36 \
  -o trimmed_reads/N61311_untrt_R1_trimmed.fastq.gz \
  -p trimmed_reads/N61311_untrt_R2_trimmed.fastq.gz \
  fastq/N61311_untrt_R1.fastq.gz \
  fastq/N61311_untrt_R2.fastq.gz \
  > trimmed_reads/N61311_untrt_cutadapt.log
Parameter Meaning
-a 3’ adapter sequence for Read 1 (Illumina TruSeq)
-A 3’ adapter sequence for Read 2 (Illumina TruSeq)
-q 20 Trim bases with quality score below 20 from read ends
-m 36 Discard reads shorter than 36 bp after trimming
-o Output file for trimmed Read 1
-p Output file for trimmed Read 2 (paired-end mode)
> .log Save trimming statistics to a log file

Check the trimming log:

cat trimmed_reads/N61311_dex_cutadapt.log

Look for:

  • Total read pairs processed: Should match your input (100,000)
  • Reads with adapters: How many reads had adapters removed
  • Pairs that were too short: Should be a small number

Step 5: Run FastQC on trimmed reads

Run FastQC again on the trimmed reads to verify quality improvement.

mkdir -p fastqc_trimmed
fastqc -o fastqc_trimmed trimmed_reads/*.fastq.gz

Compare the trimmed reports to the raw reports:

  • Adapter content should be reduced or eliminated
  • Per-base quality at the ends of reads should improve

Step 6: Exit the container

exit

Your files are safe! All output files were written to /data inside the container, which is your workshop folder on your computer. You can verify this by opening your workshop folder in your file browser.
